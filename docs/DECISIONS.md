# Engineering decision log

These are implementation decisions made to build Phase 1. None of them changes a confirmed product
decision. Where a decision touches an OPEN item (OD-xx / release gate Gx), it is a **reversible,
configurable default** and still needs product-owner approval before launch.

| ID | Decision | Why | Touches | How to change |
|---|---|---|---|---|
| D-01 | **Single Next.js 16 (TypeScript) service** for UI, API and server logic. No separate FastAPI backend. | PRD §10.3 approves no stack and asks for solo-builder feasibility. One deployable, shared types, server components keep secrets server-side. Nothing in the requirements needs Python. | OD-09 | Retrieval/AI modules in `src/lib/ai` have no framework dependencies and could be moved behind an HTTP service. |
| D-02 | **PostgreSQL via Drizzle ORM; embedded PGlite for development and tests.** | Postgres meets provenance, constraints (partial unique index for "one published version"), FTS and future pgvector. No Docker daemon was available; PGlite runs real Postgres in-process. | OD-09 | `DATABASE_URL` switches to a server; migrations in `drizzle/`. |
| D-03 | Next.js `cacheComponents` **disabled**. | Every main route depends on the authenticated session and session language; session-derived data should not be cached. | NFR-01 | Re-enable per route later with Suspense boundaries if performance requires. |
| D-04 | **Own session/OTP auth + Arctic for Google/Apple** rather than a hosted auth vendor. | Full control of minimal data (FR-18), safe linking rules (FR-02), no vendor selection made (OD-04). Tokens and codes stored hashed; delivery providers pluggable (Resend, Twilio). | OD-04, G3 | Replace `src/lib/auth/*`; pages call only `requireUser()` / `startSession()`. |
| D-05 | **Account linking:** a provider identity links to an existing account only when the provider asserts a *verified* email; otherwise sign-in is refused with a recovery message (no silent duplicate). | FR-02 "linking requires proof of control", PRD §6.3 auth failure. | OD-04 | `resolveOAuthUser` in `src/lib/auth/oauth.ts`. |
| D-06 | **Language is session-scoped** (stored on the session row; asked after each sign-in). | IA default for OD-14 when privacy review has not approved persistence. | OD-14, G4 | Add a `language` column on `users` once approved. |
| D-07 | **Keyword retrieval (Postgres FTS + lexical coverage scoring)**; no embeddings/pgvector yet. | Corpus is small (pilot); no embedding provider is configured; keyword evidence is inspectable. Wikipedia's own search adds broader recall. | OD-09 | Add an embedding column to `corpus_passages` and a provider in `retrieval.ts`. |
| D-08 | **External retrieval = Wikipedia (MediaWiki API), configurable, tier 2 (tertiary).** Revision-pinned permalinks are cited. | Only keyless retrieval available; multilingual (all 11 languages have Wikipedias). Tier influences ranking only, never truth (FR-08). | BR-05, OD-09 | `RETRIEVAL_PROVIDERS`; add specialist/academic providers in `retrieval.ts`. |
| D-09 | **LLM provider abstraction** with two implementations: Anthropic Claude (`claude-opus-5-5`, structured outputs, server-side refusal fallback) and **Groq** (`openai/gpt-oss-120b`, strict JSON-schema output, one bounded retry on rate limits). Local development currently uses Groq. Without a key, Ask shows retrieved evidence only — never a simulated answer. | Replaceable vendor (prompt §7A); honest degraded state. | OD-09 | `src/lib/ai/llm.ts` (`LLMProvider`). |
| D-10 | **Fail-closed answer checks** (see `docs/AI_QUALITY.md`). Thresholds are provisional env values. No language is gate-passed by default, so every answer currently renders as *"Shown with limitations"*. | FR-12, IA §2. Missing thresholds are an OPEN gate; we do not pretend they exist. | OD-01, OD-02, G1, G2 | `ANSWER_*`, `QUALITY_GATE_PASSED_LANGUAGES`. |
| D-11 | Images embedded in the design document are used **only as labelled development placeholders** (`public/images/dev`). Kolkata and Madurai use typographic panels instead of unrelated stock imagery. | Design §4 requires usage rights and verified captions; rights are undocumented. | Design §4 | Replace `image` entries in `content/cities.json` / story `hero` with rights-cleared assets (`rightsCleared: true`). |
| D-12 | **Accessibility adjustment:** terracotta `#B85E43` is ~4.1:1 on warm paper (fails AA for small text), so small terracotta text uses `#994A33` (~5.6:1). All other tokens are as specified. | Design §2 asks to test real pairings; WCAG 2.2 AA is the recommended target. | NFR-05 | `src/app/globals.css`. |
| D-13 | Typography: **Noto Serif** (display) + **Noto Sans** with the nine Noto Sans Indic families. | Design §3 recommends evaluating Noto for coverage of all 11 scripts. Not a final brand decision. | Design §3 | `src/app/fonts.ts`. |
| D-14 | **Development fixtures**: six stories and three connections written with AI assistance from revision-pinned Wikipedia articles (52 verbatim excerpts, verified). Flagged `is_fixture`, labelled in every view, auto-published only by the dev seed with an audit entry, and excluded in production unless `ALLOW_FIXTURE_CONTENT=true`. | The product needs exercisable content; the real inventory (OD-06) does not exist and must not be faked. | OD-06, BR-03 | Delete `content/fixtures/` before launch; add editorial content under `content/`. |
| D-15 | Report categories use the **Design's six**, mapped to the PRD's four for reporting (`CATEGORY_TO_PRD`). Reports are anonymous (no user id). | Resolves C6 with a superset; FR-19 "no unnecessary personal details". | FR-19, OD-15 | `src/lib/reports.ts`. |
| D-16 | Reporting an AI answer attaches the question/answer text **only if the reporter keeps the box ticked** (default ticked, clearly labelled). Answers are otherwise not stored. | Editors cannot review an answer they cannot see; question text is excluded from analytics and audit logs. | FR-19, FR-20, OD-05 | `report-form.tsx`; consider default-unticked after privacy review. |
| D-17 | **Shared links require sign-in**, preserving the destination. | IA default for G6, consistent with confirmed mandatory account. | G6 | `src/proxy.ts` `PUBLIC_PREFIXES`. |
| D-18 | **Self-service account deletion** hard-deletes the user, identities and sessions immediately. | Minimal data means nothing else references the user; a user-initiated deletion is the least surprising behaviour. Retention/deletion policy itself remains OPEN. | OD-05, G4 | `src/app/(app)/settings/account/page.tsx`. |
| D-19 | Editorial roles: a **single `editor` role** that can review, approve and publish; granted via CLI (`npm run editor:grant`). AI is never an approver; fixture auto-publication is a separate, audited system path disabled in production. | IA §2: "start with one authorised editor role". Separate roles remain OPEN. | OD-08, G5 | `users.role` enum + checks in `workflow.ts`. |
| D-20 | Rate limiting and the Wikipedia response cache are **in-process memory**. | Single-instance pilot; avoids adding Redis without a real workload. | NFR-10 | Move to a shared store before running multiple instances (see DEPLOYMENT.md). |
| D-21 | Sensitive-topic handling uses a **provisional keyword taxonomy** combined with the model's own risk label (model can only raise risk). High-risk → abstain; sensitive → never routine-approved, requires perspectives or limits. | OD-03 is open; deterministic and auditable default. | OD-03, FR-11 | `src/lib/ai/sensitivity.ts`. |
| D-22 | Non-English UI catalogues are **AI-drafted, unreviewed**, covering core-journey labels (65–66 of 281 strings, 23%); missing strings fall back to English with a visible banner. No story translations exist. | Full multilingual support is confirmed direction but cannot be claimed without review (FR-03, §9.4). | OD-01, G1 | `src/lib/i18n/messages/*.ts`; see LANGUAGE_READINESS.md. |
| D-23 | **Demo mode** (`DEMO_MODE=true` + `EMAIL_PROVIDER`/`SMS_PROVIDER=screen`): the one-time code is shown on the verify screen instead of being sent; verification still happens, the header shows a "Demo" label, and production refuses on-screen codes unless `DEMO_MODE=true` is explicit. | Lets people experience the journey without paid SMS or a verified email domain. Not authentication for real users. | FR-02, OD-04 | Remove the three variables and configure Resend/Twilio. |
| D-24 | **Visual theme switched to "Cinematic" (dark, image-led)** at the product owner's request, modelled on a supplied reference: full-bleed photo heroes with scrims, frosted panels, ivory pill buttons and chips, a floating circular bottom nav, Plus Jakarta Sans for Latin text (Noto for Indic scripts). The reference's travel elements (prices, trip duration, "Plan your tour") were not adopted — out of scope (PRD §5.2); fact pills show story sections/sources/connections/language and the CTA is "Ask about this story". Contrast checked: body text 17:1, secondary 7.8:1; photo text sits on top and bottom scrims. Supersedes the light Living Editorial Atlas tokens (Design §2) and the D-12 terracotta adjustment. | Product-owner direction; Design doc ranked this direction #2, with readability as the main risk, mitigated by the scrims and contrast values. | Design §2–§4, NFR-05 | Tokens in `src/app/globals.css`; `PhotoHero`/`FactPills` in `src/components/hero.tsx`. |
| D-25 | **Email goes through Supabase Auth only; Resend removed** at the product owner's request. Codes are generated and verified by Supabase, and the emailed `/auth/confirm` link is gone. | Supabase Auth only sends auth emails, so NDA acceptances are no longer emailed to legal; see D-26. |
| D-26 | **NDA is enforced after sign-in, on every path,** by `requireUser` and the ask/report APIs, with each acceptance stored in `nda_acceptances` (signer, version, IP, browser, time). Legal exports it with `npm run legal:nda-export`. Existing users accept once. | Every sign-in path can create an account, so a sign-up form alone cannot enforce it. Updating `NDA_AGREEMENT_TEXT.version` asks everyone to accept again. |
| D-27 | **RLS is on for every table with no policies.** Data access goes only through the server's owner connection; Supabase's REST API with the public anon key gets nothing. | The tables were readable and writable with the anon key. Every new table's migration must enable RLS; a test enforces it. |
